# Design: Edit opening hours with natural language

## Context

See `proposal.md` for the motivation, and the three spec deltas for the required behavior (`business-editing`, `directory`, `infrastructure`). What shapes the approach:

- **Backend.** `app.ts` exposes one route, `GET /businesses`, and receives its work as plain functions. `handlers/lambda.ts` wires the real clients and creates them on every request, so nothing is kept between invocations. The repository runs SQL through `execute(sql, parameters)` of `db/dataApi.ts`, which already supports named string parameters. `domain/openingHours.ts` has the read validator, `normalizeOpeningHours`, which returns `[]` for anything invalid.
- **Infrastructure.** The Lambda has a 10-second timeout and no VPC, so it can reach the Anthropic API over the internet. The HTTP API allows only `GET` in CORS. The role has exactly three permissions.
- **Frontend.** The dialog gets its business from the query data, and `strings.ts` holds every text. `formatOpeningHours` already turns a week into the lines of the "Horario" row. The `QueryClient` sets defaults only for queries, so mutations are not retried.
- **Model.** Claude Haiku 5.5 (`claude-haiku-5-5`), chosen by the owner for cost: $0.10 per million input tokens and $0.50 per million output tokens. It thinks by default with effort `medium`, it rejects `temperature` and prefill, and its refusals have no server-side fallback.

## Goals / Non-Goals

**Goals:**

- A fixed workflow with one model call, not an agent: read hours → interpret → validate → preview → confirm → write. The code decides every step.
- The model never writes and never decides authorization. Its output is data that the domain validates like any other input.
- Every new module is testable without network: the model, SSM, and the database are passed in as functions.

**Non-Goals:**

- No tool calling, no conversation history, no retry with the validator's feedback. The eval decides later if a retry is worth a second call.
- No prompt caching. The system prompt is shorter than the minimum cacheable prefix for this model, so a cache breakpoint would do nothing.
- No change to `GET /businesses` or to the read validator.

## Decisions

| # | Decision | Alternatives discarded | Why |
|---|---|---|---|
| D-1 | Two routes. `POST /businesses/{id}/opening-hours/interpretation` calls the model and never writes. `PUT /businesses/{id}/opening-hours` validates and writes, and never calls the model. | (a) One route that interprets and saves. (b) A preview flag on one route. | The preview is a human approval gate: what is stored is exactly the week the admin saw, sent back by the client and validated again. The `PUT` is idempotent and testable without any model. A flag would mix two behaviors in one handler. |
| D-2 | The model gets the stored hours and returns the **full week**, not a patch. The frontend computes the changed days by comparing the two weeks. | The model returns operations such as "set Saturday to 08:00–14:00". | A full week reuses the existing `OpeningHoursRange[]` shape and validators. A patch format would be new, and the model could get its format wrong as well as its content. A diff in code is exact and testable, and a wrong diff in the preview exposes a model mistake. |
| D-3 | The call uses `client.messages.create` with `output_config.format` of type `json_schema`: `{ understood: boolean, openingHours: [{ dayOfWeek: 1–7 as an enum, opens: string, closes: string }] }`, every object with `additionalProperties: false`. `output_config.effort` is `low`, `max_tokens` is `4000`, and `thinking` and `temperature` are not sent. | (a) `client.messages.parse` with `zodOutputFormat`. (b) A tool with `strict: true`. (c) Asking for JSON in the prompt and parsing free text. | (a) needs `zod`, a third new package. (b) works, but a tool is a detour when the goal is only a response shape. (c) has no shape guarantee. The schema guarantees the shape, and the domain still checks the meaning (D-6), since a pattern for `HH:MM` and number ranges are not supported in the schema. `low` effort is enough to read a schedule and keeps the call short. |
| D-4 | `backend/src/interpretation/openingHoursInterpretation.ts` exports `interpretOpeningHours({ storedHours, request }, callModel)`. `callModel(params)` returns the SDK message. The module reads `stop_reason`: `end_turn` parses the single text block, `refusal` returns `understood: false`, and anything else (`max_tokens`, no text block, JSON that does not parse) throws `InterpretationUnavailable`. A proposal that fails D-6 returns `understood: false`. The route answers `{ "understood": false }` without `openingHours`, whatever the model returned in that field. | Calling the SDK inside the module. | The same pattern as `execute` in the repository: tests pass a fake `callModel` with fixed responses, so they are fast, free, and deterministic (AGENTS.md: tests never hit the network). |
| D-5 | The prompt lives in `backend/src/interpretation/openingHoursPrompt.ts`, in English, with a `PROMPT_VERSION` constant. The system prompt states the task, the rules of "Opening hours validity" and "Opening hours for writing", that days the request does not mention keep their stored ranges, that `understood` is `false` for anything that is not a change of hours, and two short examples. The user message holds the stored week as JSON in `<stored_hours>` and the request in `<request>`, with the instruction that the request is data to interpret, never instructions. No date or time is sent. | (a) The prompt in Spanish. (b) Sending today's date for requests like "mañana". | Instructions in English and data in Spanish is the project's language split. Without a date, the model cannot be asked for date-based hours, which are out of scope. The version is logged, so a prompt change can be tied to eval results. |
| D-6 | `validateOpeningHoursForWriting(value: unknown)` in `domain/openingHours.ts` returns `{ valid: true, ranges }` sorted, or `{ valid: false, problems: string[] }` in English. It reuses the existing range check and adds the overlap rule: two ranges of the same day overlap when one opens before the other closes. `normalizeOpeningHours` does not change. | (a) Reusing `normalizeOpeningHours` and treating `[]` as invalid. (b) Silently dropping the overlapping range. | (a) cannot tell "no hours" from "invalid", and `[]` is a valid week to store. (b) would store something the admin did not see. The problems are for the logs and the tests; the API only answers `invalid_opening_hours`. |
| D-7 | `requireAdminKey(readAdminKey)` is Express middleware on the two editing routes. It reads `Authorization`, accepts only `Bearer {key}`, and compares the SHA-256 digests of both keys with `crypto.timingSafeEqual`. It runs before the body is read. The JSON body parser is added only to those routes, with a 4 KB limit. | (a) `===`. (b) An API Gateway Lambda authorizer. (c) IAM authorization on the routes. | (a) leaks timing. Hashing first gives both buffers the same length, which `timingSafeEqual` requires. (b) is a second function and more infrastructure for one shared key. (c) needs signed requests, which a browser cannot make without AWS credentials. `node:crypto` is part of Node 24, so no package. |
| D-8 | Secrets are SSM `SecureString` parameters `/alameda/{env}/admin-key` and `/alameda/{env}/anthropic-api-key`, under the AWS managed key `aws/ssm`. The Lambda gets only their names, in `ADMIN_KEY_PARAMETER` and `ANTHROPIC_API_KEY_PARAMETER`, and reads them with `GetParameter` and `WithDecryption: true` on each request that needs them. The Anthropic key is read only after the admin key matched and the business was found. | (a) Caching the values in a module variable. (b) The AWS Parameters and Secrets Lambda Extension. (c) Secrets Manager. (d) Lambda environment variables with the values. | (a) breaks the rule in `lambda.ts` and AGENTS.md that nothing is kept between invocations, and a changed key would wait for new instances. Two reads add tens of milliseconds to a request that waits on a model anyway. (b) adds a layer to the template. (c) charges per secret for rotation neither key needs (owner's choice). (d) puts the values in plain text in the console, which the infrastructure spec forbids, and CloudFormation cannot create `SecureString` parameters. |
| D-9 | The role adds `ssm:GetParameter` on the two parameter ARNs, built with `!Sub` from `AWS::Region`, `AWS::AccountId`, and `Environment`, and `kms:Decrypt` on `arn:aws:kms:${AWS::Region}:${AWS::AccountId}:key/*` with the conditions `kms:ViaService` = `ssm.${AWS::Region}.amazonaws.com` and `kms:EncryptionContext:PARAMETER_ARN` equal to one of the two parameter ARNs. | `kms:Decrypt` on `*` with no condition. No `kms:Decrypt`. | The SSM guide says decrypting needs `kms:Decrypt`. The conditions limit it to SSM decrypting these two parameters, so the role can decrypt nothing else. Task 6.2 checks in `dev` that a read works and that another parameter is denied. |
| D-10 | The repository adds `findActiveBusinessOpeningHours(execute, id)`, a `SELECT opening_hours::text ... WHERE id = CAST(:id AS uuid) AND is_active = true`, and `updateActiveBusinessOpeningHours(execute, id, openingHoursJson)`, an `UPDATE businesses SET opening_hours = CAST(:openingHours AS jsonb) WHERE id = CAST(:id AS uuid) AND is_active = true RETURNING id::text AS id`. The service checks the id against a UUID pattern first, and no returned row means `404`. | (a) An ORM or query builder. (b) Letting the cast fail for a bad id. | (a) is forbidden. (b) turns a client error into a `500`. The `WHERE is_active` in the `UPDATE` closes the gap between reading and writing. The stored hours given to the model go through `normalizeOpeningHours`, so invalid stored hours are sent as `[]`. |
| D-11 | The Anthropic client is created per request with `timeout: 7000` and `maxRetries: 0`. The model ID `claude-haiku-5-5` is one constant in the interpretation module. The Lambda timeout stays at 10 seconds. | (a) The SDK defaults (10-minute timeout, 2 retries). (b) A longer Lambda timeout. (c) The model ID in an environment variable. | (a) would let the Lambda time out first and return a gateway error with no body. With no retries, a slow model gives a clean `503` within the budget: two SSM reads, one database read, and 7 seconds for the model. (b) is not needed for one call at `low` effort; task 6.3 measures it. (c) A model change must come with an eval run and a reviewed PR, so a constant is the safer place. |
| D-12 | Each editing request writes one JSON log line: route, outcome (`saved`, `understood`, `not_understood`, `unauthorized`, `not_found`, `invalid`, `unavailable`, `error`), latency, and for interpretations the `PROMPT_VERSION`, `stop_reason`, and input and output tokens. Never headers, keys, or the request text. | Logging the request and the model output to debug prompts. | The directory spec forbids logging request headers, and the request text can hold anything. The eval is the place to study prompt behavior. |
| D-13 | Frontend: `isAdminMode(search)` in `features/businesses/adminMode.ts`, read once in `Directory` and passed to the dialog as a prop. `features/businesses/adminKey.ts` gets, sets, and clears the key in `sessionStorage`, each call inside `try`/`catch` so a blocked storage just asks again. `frontend/src/api/openingHours.ts` has `interpretOpeningHours` and `saveOpeningHours`, which throw `UnauthorizedError` on `401`. Two hooks wrap them with `useMutation`, and the save hook invalidates `BUSINESSES_QUERY_KEY` on success. | (a) A context provider for admin mode. (b) Keeping the key in React state only. (c) `localStorage`. | (a) is one boolean used by one component. (b) would ask for the key on every reload. (c) keeps the key after the tab closes, against the spec. Mutations hold the request state, so no server data is copied into other state (AGENTS.md). |
| D-14 | `OpeningHoursEditor.tsx` renders the panel inside the "Horario" row, and holds only UI state (text, key field, which step is shown). Pure functions in `features/businesses/openingHours.ts`: `changedDays(stored, proposed)` returns day numbers, and `formatDayList(days)` returns lowercase names: "sábado", "sábado y domingo", or "lunes, miércoles y sábado". The status texts are in a `role="status"` region. | A state machine library. | Five steps fit in a `useState`. Pure functions carry the logic the spec fixes, so they are tested without rendering. |
| D-15 | CORS adds `POST` and `PUT` to `AllowMethods`, and `AllowHeaders: [authorization, content-type]`. The HTTP API answers the preflight itself. | Handling `OPTIONS` in Express. | API Gateway already owns CORS for this API (infrastructure spec, "Cross-origin access"). |
| D-16 | The eval: `backend/eval/openingHours/cases.json` holds about 20 cases `{ name, storedHours, request, expected }`, covering one-day changes, whole weeks, split days, "24:00", "cerrado", ambiguous text, off-topic text, and an injection attempt. `backend/scripts/evalOpeningHours.ts` runs each case through `interpretOpeningHours` with the real client and the developer's `ANTHROPIC_API_KEY`, and prints per case pass or fail, the exact-match accuracy, the total tokens, and the cost. A pure `scoreCase(expected, actual)` is unit-tested. | (a) An eval job in CI. (b) An LLM judge. | (a) CI has no secrets and must not call the network. (b) The expected answer is a week, so an exact comparison after sorting is enough. About 20 calls cost well under a cent. |
| D-17 | New packages in `backend`: `@anthropic-ai/sdk` (1.8.0, checked on 2026-11-11) and `@aws-sdk/client-ssm` (3.1167.0, the same release line as `@aws-sdk/client-rds-data`). The Anthropic API is added to the services table of `docs/dependencies.md`. | (a) Raw `fetch` to the Anthropic API. (b) The AWS SDK that the Node.js 24 runtime includes. | (a) means writing typed errors, retries, and types the SDK already has, and the project's rule is to use the official SDK. (b) The bundle pins versions through the lockfile, as it already does for the RDS client. |
| D-18 | The text box has `maxLength={300}` and the Tailwind utilities `field-sizing-content`, a minimum height of about two lines, and `max-h` of about six lines with `overflow-y-auto`. The AI border is a wrapper with 2 px of padding and a `conic-gradient(from var(--ai-border-angle), …)` background in two new tokens, `--color-ai-from` (blue-500) and `--color-ai-to` (violet-500) of the Tailwind 4.3 default palette as sRGB hex, like the category tokens. `--ai-border-angle` is registered with `@property` as an `<angle>` in `index.css`, and `@theme` defines `--animate-ai-border-spin` (one turn in 4 s, linear, infinite). The animation class applies only while interpreting, through a `data-interpreting` attribute, and `motion-reduce:animate-none` stops it. A sparkle SVG with `aria-hidden="true"` joins `icons.tsx`. The existing `focus-visible` outline in `ink` stays on the text box. | (a) A JavaScript auto-resize that sets the height from `scrollHeight`. (b) Animating the border all the time. (c) An animated GIF or a library. | (a) is an effect and a ref for something CSS now does; in a browser without `field-sizing` the box keeps a fixed height and scrolls, which is acceptable for an admin screen. (b) Motion that always runs distracts and spends battery; turning only while the model works makes the motion mean "working" (owner's choice). (c) adds assets or a package. Custom CSS stays in the Tailwind entry file and colors are tokens (AGENTS.md, "Styling"). |

Documentation checked on 2026-11-11:

- AWS CloudFormation template reference, `AWS::SSM::Parameter`: "Parameters of type `SecureString` are not supported by AWS CloudFormation."
- AWS Systems Manager User Guide, "How AWS Systems Manager Parameter Store uses AWS KMS": decrypting a `SecureString` needs `kms:Decrypt`, and the `aws/ssm` key policy cannot be changed. The guide does not say if `aws/ssm` needs the IAM permission, so task 6.2 checks it.
- AWS Systems Manager User Guide, "Parameter Store throughput": 40 transactions per second by default, shared by the `GetParameter` actions. Extra charges apply only to the higher throughput setting.
- Claude API documentation (structured outputs, effort, stop reasons, Claude Haiku 5.5): supported JSON Schema features (no `pattern`, no numeric ranges), `output_config.format`, `stop_reason` values, and pricing.
- npm registry: `@anthropic-ai/sdk` 1.8.0 and `@aws-sdk/client-ssm` 3.1167.0.
- Tailwind CSS 4.3.3 (the installed version): the `field-sizing-content` utility, the `motion-reduce` variant, and `--animate-*` theme variables in `@theme` (D-18).
- MDN, CSS `field-sizing`: Baseline 2026, newly available since June 2026. MDN, CSS `@property`: Baseline 2024, newly available since July 2024.

## Risks / Trade-offs

- [The model misreads a request and the admin saves it without reading] → The preview shows the full week and the changed days, and nothing is stored until "Guardar". The eval measures accuracy before `prod`.
- [Prompt injection in the request] → The model has no tools and can only return a week. The week is validated and must be confirmed by the admin, who is also the only one who can send requests.
- [The admin key leaks, for example on a shared screen] → Overwrite the parameter with the documented command. The next request uses the new key, since nothing caches it (D-8). Each environment has its own key.
- [Someone guesses the key] → It is 32 random bytes (generated with `openssl rand -base64 32`), and a wrong key costs one cheap `401` with no model call. Rate limiting stays excluded (infrastructure spec).
- [A later data migration overwrites hours that were edited in `prod`] → The deployment documentation says that a data migration that sets `opening_hours` must first read the current `prod` value.
- [Two edits at the same time] → The last save wins. With one admin this is accepted.
- [A slow model or a cold start reaches the Lambda timeout] → The 7-second client timeout gives a clean `503` first (D-11). Task 6.3 measures the real times.
- [Anthropic API spending] → Only the admin can call the model. The documentation recommends a monthly spend limit in the Anthropic Console, set by hand.
- [The request and the hours are sent to Anthropic] → They hold only public business information. Neither is logged (D-12).
- [The Lambda bundle grows] → Both SDKs are bundled by esbuild. Task 6.3 compares cold start and `GET /businesses` times with the performance check of the infrastructure spec.

- [An older browser without `field-sizing`] → The text box keeps its minimum height and scrolls. Nothing breaks, and the admin can use a current browser.
- [The moving border hides where the keyboard focus is] → The `focus-visible` outline stays on the text box itself, and task 6.1 checks it with the keyboard.

## Migration Plan

1. Install the two packages after the owner's approval and record them in `docs/dependencies.md`.
2. Create the two `dev` parameters with the documented `aws ssm put-parameter --type SecureString` commands, then deploy `dev`.
3. Run the checks of tasks 6.1 to 6.3 and the eval in `dev`.
4. Create the two `prod` parameters, with different values, and deploy `prod`.
5. Rollback: redeploy the previous backend and frontend. The parameters can stay, since the old Lambda ignores them, and the stored hours keep their format.
